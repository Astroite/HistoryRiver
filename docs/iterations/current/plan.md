# M1-01 迭代计划：核心体验原型

> 状态：进行中  
> 周期：2026-07-16 起，完成条件驱动  
> 产品阶段：P0——核心视觉语义与空间交互验证

## 1. 上下文

首轮讨论已经确定产品母题、目标用户、历史范围与关键视觉语义，详见 [体验设计文档](../../design.md)。本迭代不再扩展宏观概念，而是回答一个更具体的问题：

> 用户能否在没有旁白和大量文字解释的情况下，从同一空间中读出“历史长河、二十年切片、人物一生、事件聚散和思想传承”五层含义？

从本迭代起，长期基线拆为两份：

- `docs/design.md` 只维护产品、体验、视觉、声音、内容和设计验证结论；
- `docs/tech.md` 只维护实现架构、数据合同、性能预算、技术验证与降级策略；
- 当前迭代的临时假设、过程证据和任务状态只写入 `docs/iterations/current/`，经验收后再回写长期基线。

## 2. 迭代目标

产出一段可交互的桌面端 P0 原型，以模拟的诸子百家数据完整走通：

1. 从“今天”仰望九天长河；
2. 选择并显影一个二十年观察窗口；
3. 镜头从侧面总览进入斜向穿行，再转为俯视切片；
4. 看到人物沿生命轨迹移动并在事件处聚集；
5. 区分人物丝线与思想传承丝线；
6. 聚焦一个人物并沿一条思想关系继续探索；
7. 返回全史视角且不丢失时间与空间方向感。

## 3. 迭代范围

### 3.1 范围内

- 桌面浏览器、单一屏幕、鼠标/触控板和键盘；
- 一个受控的二十年观察窗口，不制作完整全史数据；
- 12–20 位模拟人物、2 个策划事件、3–5 条思想关系；
- 全史远景、进入窗口、事件聚集、人物聚焦、思想溯源五种核心状态；
- 基础声音状态接口，可先用占位声音验证触发与混合，不制作正式配乐；
- 设计可理解性观察与技术性能采样；
- 低动态、静音和基础键盘回退路径的最小验证。

### 3.2 范围外

- 真实的 30–50 位首章完整人物数据及史料审校；
- 三皇五帝至 1949 年的全量内容；
- 正式时代纹样、音乐、字体授权与最终美术资产；
- 影响力历史评分模型的定稿；
- 人民/无名之流的真实统计映射；
- 账号、收藏、分享、社区、移动端和生产部署；
- WebGPU 专属效果或必须依赖高端显卡才能成立的表现。

## 4. 固定约束

- 诗意表达不能改变时间、地理、关系和证据状态的基础语义；
- 三种观察角度必须来自同一套坐标和对象状态；
- 镜头默认引导，但用户可随时接管且不会被强行夺回；
- 原型使用模拟数据时必须显式标注，不得与史实内容混用；
- 不以牺牲基本可读性换取粒子数量；
- `main` 保持稳定，本迭代不在未验收时归档。

## 5. 依赖与前置条件

- 产品与体验依据：`docs/design.md`；
- 技术实现依据：`docs/tech.md`；
- 本机需具备可运行的前端工具链和支持硬件加速的桌面浏览器；
- P0 可使用确定性生成的模拟数据，真实内容研究不是实现前置依赖；
- 正式声音和时代视觉研究可后置，但状态接口需在 P0 中预留。

### M1-01-T01：建立双文档与迭代基线

**任务上下文**：原概念文档同时包含体验愿景、技术问题和下一步建议，难以作为迭代期间的稳定合同。

**执行内容**：

- 将长期文档拆为 `design.md` 与 `tech.md`；
- 在两份文档中标明确认项、设计/技术假设、待验证项；
- 建立 `current/README.md`、`plan.md`、`work-log.md`；
- 建立需求到技术验证的追踪表。

**完成条件**：

- 两份主文档职责无歧义并相互链接；
- 当前迭代具有范围、依赖、Task 和可执行验收；
- 不丢失原文档中的任何已确认产品结论；
- Markdown 内部链接与目录结构可检查通过。

### M1-01-T02：冻结 P0 体验合同

**任务上下文**：技术原型需要明确“必须看见什么、何时发生、如何判定理解”，而不是只实现一个好看的粒子场。

**执行内容**：

- 定义五个核心状态及其进入/退出条件；
- 定义 60–90 秒默认导览的镜头节拍；
- 定义光点、人生悬丝、事件点云和思想丝线的最小视觉差异；
- 定义观测任务、口述问题和通过阈值。

**完成条件**：

- 每个状态都有画面目标、用户动作、系统反馈和失败信号；
- 导览允许随时接管与返回；
- 至少五项核心视觉语义具有可测试的识别标准；
- 设计验收不依赖实现者的主观“看起来不错”。

### M1-01-T03：实现同源三视角技术切片

**任务上下文**：最关键的技术假设是同一数据和坐标能同时支撑光瀑远景、斜向穿行与山河切片。

**执行内容**：

- 建立最小前端工程与确定性模拟数据；
- 实现统一世界坐标、人物点、生命轨迹、事件聚散和思想关系；
- 实现三种相机姿态、二十年窗口与状态切换；
- 实现对象拾取、人物聚焦和返回路径；
- 接入性能与状态调试面板。

**完成条件**：

- 三种视角复用同一对象标识、时间和位置数据，不复制三套场景；
- 用户可完成本计划第 2 节的七步路径；
- 默认质量档达到 `tech.md` 中 P0 性能门槛；
- 模拟数据标识、调试开关和复现实验种子可见。

### M1-01-T04：执行设计与技术验证

**任务上下文**：P0 的目的不是证明方案正确，而是尽早暴露视觉语义偏差与性能上限。

**执行内容**：

- 完成内部启发式走查；
- 完成 S0–S4、导览接管、低动态和质量降级的开发者自验；
- 记录视觉语义、镜头接管、方向锚点、线型分层和不适风险；
- 在目标设备与降级设备上记录帧时间、对象规模和交互延迟；
- 将结论分为保留、调整、否决和待复测。

**完成条件**：

- C-01 至 C-07 均具有可复现的结构化自验记录；
- 核心视觉语义均符合设计文档的自验条件，或形成明确修订 Task；
- 技术结果包含设备、浏览器、质量档、数据规模和采样方法；
- 失败项不得通过改写解释掩盖，必须回到设计或技术假设。

### M1-01-T05：收尾、回写与归档

**任务上下文**：迭代过程文档不是长期产品真相，只有经验收的结论才进入主文档。

**执行内容**：

- 逐项核对 T01–T04 验收；
- 将验证后的体验结论回写 `design.md`；
- 将验证后的实现与预算结论回写 `tech.md`；
- 在 `work-log.md` 写复盘、遗留问题和下一迭代候选；
- 将整个 `current/` 归档到 `archive/M1-01/`。

**完成条件**：

- 所有任务完成或明确取消并说明原因；
- 长期文档与实际原型一致；
- `current/` 不再保留活跃内容；
- 下一迭代只能在归档后创建。

## 8. 风险与应对

| 风险 | 早期信号 | 本迭代应对 |
| --- | --- | --- |
| 光点与线条成为不可读的“光污染” | 固定视口中人物、事件与关系没有清晰视觉主次 | 先限制对象规模，以语义分层和选择性显隐优先 |
| 纵向时间与俯视地图切换造成迷失 | 接管后无法回到年份或原视角 | 保留时间方向标、窗口锚点和一键返回 |
| 镜头导览引发眩晕 | 快速穿行时出现回避或不适 | 限制角速度、避免突然加速、提供低动态模式 |
| 模拟数据被误认为历史结论 | 固定视口或信息面板未见“模拟数据”与证据类型标识 | 常驻“模拟数据”标识并使用虚构/占位标识 |
| 性能优化破坏语义 | 降级后人物或关系直接消失 | 先降采样、光效和分辨率，再降非核心背景密度 |

## 9. 变更规则

- 新需求若不直接服务于 D-01 至 D-06 或 T-01 至 T-03，回到下一轮讨论；
- 当前 Task 内允许修复验收失败，但不得顺带扩展全史数据、正式美术或生产功能；
- 任何阈值调整必须在 `work-log.md` 记录调整原因，不能为迁就结果而静默降低标准。
