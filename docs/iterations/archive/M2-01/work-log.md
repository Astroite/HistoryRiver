## 2026-07-18｜M2 方向纠正：年度人物轨迹数据库

### 用户纠正

- M1 中的自动悬停、自动播放、详情展示和相关产品流程并非用户需求，属于模型自行扩展；M2 不应继续围绕这些逻辑构建内容产品。
- M2 的核心是覆盖上下约五千年的人物轨迹：以人物为记录单元，以年为单位，每个历史年形成一个切片。
- 本轮不搜罗全部人物和全部事件，而是为各主要朝代/时代选择少量关键人物作为启动核心数据；数据库成立后，再依据核心数据重构河流视觉。

### 决策

- 原“首章内容契约与可信样片”计划被本次方向纠正取代，不再执行；历史启动记录保留，避免隐藏范围变化。
- M2-01 更名为“年度人物轨迹数据库与河流重构”，开发分支更名为 `codex/m2-01-annual-person-trajectories`。
- 数据分为来源观察、逐年派生和视觉投影三层。每年均有切片索引，但空白与未知不得用虚构人物或精确插值填满。
- 人物是第一记录单元；事件仅作为人物年度轨迹的可选依据或注释，本轮不建立完整事件/关系图谱。
- 正式运行时删除 UI、自动导览、五状态、悬停/拾取、选中/详情、URL 状态、产品快捷键和 OrbitControls；保留环境动画、视觉材质、流场、后处理、质量档、低动态与资源管理。
- 核心数据初步按 11 个主要时代覆盖单元组织，每单元优先 3–5 人，整体目标约 35–55 人；T01 必须进一步冻结覆盖矩阵与来源门槛。

### 结果

## 2026-07-18｜M2-01-T01 年度人物合同与覆盖矩阵

### 决策

- 冻结内容边界为公元前 2700 年至 1949 年；BCE 使用负整数、CE 使用正整数、0 非法，`yearIndex` 负责单调排序。
- 冻结 JSON 源数据、SQLite 规范库和确定性 Web JSON 三段式架构。Node 22 内置 SQLite 满足当前构建需求，不新增数据库依赖。
- 冻结来源类型为原始文献数字版本、学术出版物、具名参考工具和博物馆/大学等机构记录。
- 冻结 11 个连续时代覆盖单元，每单元目标 4 人；数量只表示 M2 策展覆盖。
- 冻结 `attested`、`bounded`、`interpolated`、`unknown` 四种互斥派生状态。插值必须单独记录规则和两个端点。

### 结果

- `model.ts` 已重构为时间、人物、来源、观察、插值、年度状态和年度切片合同。
- 公元前 2700 年为索引 0，1949 年为索引 4648，共 4,649 年；跨公元纪年从 -1 直接进入 1。
- `data/history/source/` 已建立清单、时代、来源、地域、人物、观察和插值源文件。

### 验证

- 模型测试逐年往返全部 4,649 个年份，确认无公元 0 年和排序歧义。
- 覆盖矩阵 11 个单元连续、无重叠和缺口。
- 悬空来源、重复 ID、重叠位置观察、非法年份和无端点插值均会使校验失败。

### 阻塞

- 无。
