# M2-01 迭代计划：年度人物轨迹数据库与河流重构

> 状态：已完成并归档
> 周期：2026-07-18 起，完成条件驱动
> 产品阶段：P1——长期数据基础与数据驱动视觉

## 1. 上下文与方向纠正

[M1-01](../M1-01/README.md) 建立了天河、人民光海、人物丝线、年度地理体积与基础渲染能力，但也加入了自动导览、五个体验状态、人物/关系选中、悬停拾取、详情语义和状态驱动镜头等未经用户确认的产品逻辑。

M2-01 启动时曾暂定为“首章内容契约与可信样片”。用户随后明确纠正方向：当前需要的不是一段可交互内容产品，而是一套能长期支撑上下约五千年人物轨迹的可靠、可扩展数据库，并在第一批跨时代关键人物数据成立后，用它重构河流可视化。

因此本计划完全取代原 M2-01 内容样片计划。工作问题改为：

> 如何以人物为第一记录单元、以历史年为统一切片单位，保存有来源的稀疏事实并派生可追溯的逐年轨迹，再让这些年度人物切片成为历史长河的真实几何输入？

## 2. 迭代目标

M2-01 依次完成四层结果：

1. **纯视觉基线**：删除 UI、自动导览、悬停/选择、详情、五状态流程和产品快捷键，只保留视觉与必要渲染基础；
2. **年度人物轨迹数据库**：建立版本、迁移、约束、来源、人物、轨迹观察、逐年人物状态与年度切片；
3. **跨时代核心数据**：按朝代/时代覆盖矩阵录入少量关键人物，不追求全部人物和全部事件；
4. **数据驱动河流**：人物一生由逐年状态形成连续丝线，每个历史年形成一个横向切片，全部切片沿时间轴堆叠为河流。

本轮成功不是“看起来像五千年”，而是任意可见人物、任意年度位置和任意切片成员都能追溯到数据库记录、派生规则与来源状态。

## 3. 核心数据语义

### 3.1 时间边界与年度切片

- 沿用现有作品内容边界作为 M2 基线：约公元前 2700 年至 1949 年；具体起止年写入数据集清单，后续可迁移，不散落硬编码；
- 历史纪年合同不允许无说明的公元 0 年。数据库保存历史年与单调 `yearIndex`，显示纪年和几何排序各自有唯一换算函数；
- 内容边界内每个有效历史年都有一个 `YearSlice`；没有已录入人物时，切片记录覆盖状态为空或未策展，而不是填充虚构人物；
- “每年一个切片”表示统一查询和渲染单位，不表示每年都有同等史料密度，也不表示每年发生了同等数量的大事。

### 3.2 人物是第一记录单元

每个人物至少具有：

- 稳定 ID、规范名、异名与生卒/活动年代；
- 所属时代与本轮入选理由；
- 可定位的来源记录；
- 稀疏的轨迹观察：时间或时间区间、地点或地域、活动/身份说明、证据状态和来源；
- 逐年派生状态：是否处于生命/活动范围、当年位置状态、派生方式、对应观察与不确定度。

事件、制度、作品和思想关系在 M2 中不是第一记录单元。若它们有助于说明某人的年度位置或活动，只作为轨迹观察的来源、标签或可选关联，不在本轮建立完整事件图谱。

### 3.3 事实层与派生层分离

数据库至少区分三层：

1. **来源与观察层**：史料或研究实际支持的时间、地点和活动记录；
2. **年度派生层**：根据观察区间生成的 `PersonYear`，每条记录说明 `attested`、`bounded`、`interpolated` 或 `unknown`；
3. **视觉投影层**：颜色、线宽、辉光、布局偏移和采样密度，只是渲染参数，不回写成历史事实。

禁止把两个有来源的地点之间自动补出的路径伪装为逐年行迹。允许插值时必须保存规则、端点观察和不确定度；证据不足时位置为 `unknown`，丝线可以雾化、断续或收束，但不能默默生成精确坐标。

### 3.4 年度人物状态的最小合同

概念合同如下，具体关系表和字段类型由 T01 冻结：

```ts
interface PersonYear {
  personId: string
  historicalYear: number
  yearIndex: number
  lifeState: "active" | "possibly-active" | "outside-range" | "unknown"
  location: HistoricalLocation | null
  derivation: "attested" | "bounded" | "interpolated" | "unknown"
  observationRefs: string[]
  uncertainty: number
}

interface YearSlice {
  historicalYear: number
  yearIndex: number
  personYearIds: string[]
  coverage: "curated" | "partial" | "empty" | "unreviewed"
  datasetVersion: string
}
```

年度切片可以物化为索引或构建产物，但必须能从规范化数据库确定性重建，不能成为第二套不可追溯的数据源。

## 4. 迭代范围

### 4.1 范围内

- 公元前约 2700 年至 1949 年的连续年度索引与切片清单；
- 人物、人物异名、时代、来源、轨迹观察、逐年人物状态、年度切片、数据版本与迁移；
- 双向索引：按人物查询一生逐年轨迹，按年份查询当年全部核心人物；
- 数据校验、确定性年度物化、差异报告和适合 Web 渲染的分片导出；
- 覆盖主要朝代/时代的一组关键人物种子数据；
- 初步覆盖矩阵建议分为：传说/早期文明、商周、春秋战国、秦汉、三国两晋南北朝、隋唐五代、宋辽夏金、元、明、清、晚清民国至 1949；
- 每个覆盖单元优先 3–5 位关键人物，整体目标约 35–55 人；来源质量和时代覆盖优先于凑数量；
- 人物年度轨迹、年度切片和数据库覆盖状态驱动的河流几何；
- 当前天河、云雾、入海口、人民光海、色彩、材质和后处理视觉语言的保留与复用；
- 数据完整性、可追溯性、确定性、性能和固定视口视觉验证。

### 4.2 范围外

- 搜罗上下五千年的全部人物或全部事件；
- 完整事件数据库、思想关系图谱、人物详情产品和百科式内容层；
- 自动导览、悬停、选中、点击、自动播放、状态跳转、信息浮层和产品快捷键；
- 用算法自动判断“关键人物”、自动生成史实或自动宣布思想关系；
- 把本轮策展人数当作人口、社会活跃度或客观历史重要度；
- 影响力评分模型定稿；人物线宽可以有策展/视觉权重，但必须与事实字段分离；
- 精确复原所有人物每一年的真实位置；证据不足必须保留未知；
- 全史正式地理边界、人民/无名之流人口映射、正式音频与最终美术；
- CMS、账号、协作审校后台、生产数据库服务和移动端产品交互。

## 6. 数据存储与构建策略

M2 采用“可审查源数据 → 规范化数据库 → 年度切片产物”三段式：

1. **可审查源数据**：适合版本控制和人工审阅，保存来源、人物与稀疏轨迹观察；
2. **规范化数据库**：关系约束、迁移和索引保证人物、年份、观察与来源引用完整；
3. **Web 年度切片产物**：由数据库确定性导出，按时间分块，供 Three.js 按需加载或构建时打包。

数据库引擎与源文件格式由 T01 依据版本审查、迁移、构建环境和 Web 导出能力冻结。无论选择何种引擎，都必须满足：

- Schema 有版本和迁移，不靠运行时猜字段；
- `(personId, yearIndex)` 唯一，人物与年度均有索引；
- 所有来源、观察和派生记录保持引用闭包；
- 相同输入和版本生成相同切片与校验摘要；
- 二进制运行库不是唯一不可审查的内容源；
- Web 产物可删除并从源数据/数据库重新生成。

### M2-01-T03：实现数据库、迁移与年度切片构建

**完成条件**：

- 事件只作为人物轨迹依据或注释，不扩张成事件大全。

- 处理出生、死亡、不确定年代、未知位置和有依据的位置迁移；
- 让人物数据决定可识别丝线和切片结构，环境粒子只承担非数据视觉连续；
- 复用 M1 的天河、云雾、河口、光海、色彩、材质与后处理语言；
- 删除对旧模拟 `prototypeFixture` 和状态样式的依赖。

**完成条件**：

- 任一渲染顶点能追踪到 `personId + yearIndex` 或明确标记为纯装饰；
- 同一人物跨年度保持稳定 ID，轨迹缺口与未知状态不会被精确插值掩盖；
- 任一年度横切面中的人物集合与数据库查询一致；
- 河流不会把策展人物数量伪装成人口或历史繁荣程度；
