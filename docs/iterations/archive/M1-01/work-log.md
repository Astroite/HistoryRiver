### 问题与方案演进

- 第一版海洋以大量独立谱系线和逐段随机转向生成，局部交叉、急弯和垂落线叠加后呈现“盘根错节”，不能读作统一潮汐。
- 中间方案先用连续低频方向函数组织少量主流线，再沿法向派生平行短丝束，并将海面点数由 78,000 降至 26,000、垂落点比例由 26% 降至 4.5%。该方案消除了大部分乱线，但方向函数仍在生成每条轨迹时临时计算，河口和远海也使用两套转向逻辑，尚不是真正可复用的流场数据结构。
- 最终方案保留河流主体，废弃临时 `currentSlope` 和河口独立转向公式，改为统一的静态二维流体场；海洋长线、短丝、河口汇流和浪花全部采样同一个场。

### 数据与积分

- 新增 `OceanFlowField`：规则网格同时保存标量势、归一化速度和密度；默认档为 `161 × 129`，降级档为 `105 × 81`。
- 速度由标量势的有限差分梯度得到，再通过双线性插值连续采样；轨迹使用二阶中点积分。该约束使相邻流线保持顺序，不再由逐段随机数控制转向。
- 势场在河口中心先提供向海方向的速度，左右口沿逐渐向两侧展开，远海转为横向主潮并叠加低频起伏；因此转变只发生在入海口之后。
- 密度场同时控制短丝和浪花的分布。浪花附带局部速度属性，只沿采样切向做小幅漂移，不再独立于海流运动。

### 渲染与性能

- 默认档使用 176 个主流带行（每行从河口中心向两侧积分）和 `88 × 70` 分层短丝种子网格；降级档分别为 96 行和 `50 × 40`。短丝长度仍保持约 10—30 个世界单位，表达个人或代际片段。
- 所有海洋线段合并为一个 `LineSegments` 批次，波面起伏和流光继续在 GPU 着色器中完成；流场只在场景初始化时生成和积分，不在每帧重算。
- 根据 `hardwareConcurrency`、`deviceMemory` 以及移动端视口与像素密度自动选择默认档或降级档；降级只减少网格分辨率、轨迹数量和采样步数，不改变河海语义和总体流向。

### 验证

- 模型测试扩展至 21 项，新增验证网格数组尺寸、向量归一化、河口左右展开、远海横向汇流、积分轨迹边界和轨迹—速度方向一致性。
- `npm test` 全部通过：类型检查、模型测试 21/21、生产构建、页面测试 2/2；`npm run lint` 与 `git diff --check` 通过。
- 使用软件 WebGL 检查 1366 × 768、1920 × 1080 及 390 × 844（设备像素比 2）视口；河口呈有序扇出、远海形成连续波带，默认档和自动降级档均可完整渲染，未发现应用或着色器错误。
- 对应提交：`cfb1a57 organize ocean flow field`（中间方向函数方案）、`bc3af75 model ocean as flow field`（最终统一流场）。

### 未决风险

- 当前是静态势场与 Gerstner 波组合，不是求解 Navier—Stokes 方程的实时流体模拟；若后续需要交互扰动、动态涡流或人物数据反向影响潮向，需要扩展场的时间维度，而不是重新引入逐线随机转向。
- 尚未完成目标集成显卡上的 30 秒正式帧时间采样；现有软件 WebGL 走查只能证明功能和降级路径可运行，不能替代 T04 的目标设备性能结论。
- 客户端块大于 500 kB 的既有构建警告仍存在，与本轮流场正确性无关，但继续保留在性能风险清单中。

## 2026-07-18｜T04 视觉增强：鎏金潮脊、共振光潮与星砂海

### 决策

- 保留 `OceanFlowField` 的静态势场、速度、密度与二阶轨迹积分，不修改河流主体、相机路径和历史语义；视觉增强只使用已有势值组织跨层时间相位。
- 海洋继续以金色为第一印象，冷蓝与浅紫只进入浪谷、掠射 Fresnel 和深水；约 8% 主流线升级为屏幕空间潮脊，其余仍是单像素细丝。
- 默认档增加半分辨率海洋选择性 Bloom；降级档不创建额外后期合成，只保留材质核心和外晕。深海只增加雾状微尘，不增加纵向长丝。

### 实质改动

- 波面 GLSL 新增解析高度梯度与法线；海线、河口线和浪花写入同一势值，以 170 势值单位、6.5 秒周期形成全海同步光潮。浪脊高光由波峰、视角镜面反射和光潮共同控制。
- 主流轨迹按固定 seed 和交错行号确定约 8% 主角线，批量构成单个屏幕空间 billboard ribbon；宽度约 2.2—5 CSS px，片元同时包含白金核心与柔金外晕。
- 26,000/10,000 个海面粒子新增生命周期、密度、势值、尺寸等级和有限聚脊属性；尺寸分布约为 92% 微尘、7.5% 中亮点、0.5% 高光焦点，最高等级带克制星芒。
- 新增默认 3,200、降级 1,000 个深海微尘，分布在海面下 5—42 单位，缓慢沉降并沿流向轻漂；现有 4.5% 垂落点比例未提高。
- `HistoryVisualRig` 增加视口更新入口以保持 ribbon 的 CSS 像素宽度；默认后期保留全局 Bloom，并把潮脊、河口流光和浪花核心送入独立半分辨率海洋 Bloom。

### 调校记录

- 第一轮默认档截图中，普通浪花的 HDR 能量与独立 Bloom 叠加，在画面右侧形成大面积白色光雾；提高海洋 Bloom 阈值、降低合成权重并限制普通粒子亮核后，第二轮恢复清楚的金色细丝、白金潮脊与黑色负空间。
- B1 未直接重复 `disp.xz`：粒子已经随 Gerstner 水平轨道运动，额外聚脊只使用解析坡度提供最多约 1.6 世界单位的有限上坡偏移，主要轮廓仍由波峰亮度和尺寸门控形成。

### 验证

- `npm test` 全部通过：类型检查、模型测试 23/23、生产构建、页面测试 2/2；`npm run lint` 与 `git diff --check` 通过。新增测试覆盖左右河口/远海势值连续前进和固定 seed 的完整势场确定性。
- 固定视口走查覆盖 1366 × 768、1920 × 1080、390 × 844（DPR 2）、默认动态、低动态和自动降级；未发现 WebGL 或着色器错误。证据位于本地忽略目录 `outputs/ocean-enhancement-2026-07-18/`。
- RTX 4070 Ti SUPER、Chrome Headless、1366 × 768 默认档 S0 连续 30 秒：中位约 6.9 ms、P95 约 7.0 ms、最大帧间隔约 27.7 ms；最大绘制调用 91，满足当前 P0 门槛。

### 结论与未决风险

- 保留“统一流场 + 少量宽潮脊 + 分级星砂 + 冷色深层 + 分档辉光”方向。默认档形成细丝、宽潮脊、白金扫光和亮点四级层次；低动态和降级档均保留主要形态。
- 本次正式帧时间样本不是 1920 × 1080 目标设备，也未覆盖集成显卡和 120,000 粒子规模夹具；T04 的跨设备性能结论仍待完成。

## 2026-07-18｜T04 光海核心增强收敛：真实 Bloom 分层、三级潮脊与彗星星砂

### 边界与决策

- 本轮只收敛 `C1 + A1 + A2 + B1`；不加入月光路、瀑布倒影、发光地平线、波陡空间分区、冷蓝星砂或独立碎钻层。
- 保留统一 `OceanFlowField`、河流主体、相机路径、海面粒子总数和历史语义；已有 `tier/cometSeed` WIP 继续完成，不以早于该改动的截图作为三级线宽证据。
- 全局 Bloom 参数继续为 `0.68 / 0.72 / 0.58`，半分辨率海洋 Bloom 继续为 `0.8 / 0.72 / 1.08`，合成权重保持 `0.56`。

### 实质改动

- 普通海线、潮脊、河口流光和星砂材质新增 `uBloomPass`。正常场景只写受控基础能量；海洋选择性 pass 才写超级光刃、彗星头和焦点星芒的 HDR 信号。`flowingOcean` 加入海洋 Bloom layer，`HistoryVisualRig` 增加 `setOceanBloomPass`；后期在 `try/finally` 中切换材质状态和相机 layer，保证异常路径也能恢复正常 pass。
- 默认档 352 条主路径固定分成 22 条普通潮脊、7 条超级光刃，共 29 条（8.24%）；降级档为 12 + 4 / 192（8.33%）。shader 明确使用 `halfWidthCss`：普通潮脊最终全宽 3—6 CSS px，超级光刃 6—10 CSS px。
- 主路径维持低亮度分布；短丝改为 `0.32 + density × 0.22 + random × 0.16`，运行时海线透明度由被覆写的 `0.36` 修正为 `0.28`。Tier 1 只保留稳定金丝核心，Tier 2 的选择性 HDR 核心约为 Tier 1 的 3 倍。
- 主路径和对应 ribbon 共用逐线 `cometSeed`；短丝种子为零并由 `aLayer` 排除。彗星使用 `potential / 170 - time / 9000 + seed` 的正向行波、约 8 势值单位短尾，沿势值增大方向传播；原有全海同步潮汐对线条的亮度/透明度贡献减半。低动态令 `uFlow = 0`，彗星、波面和星芒相位冻结。
- 星砂保持默认 26,000、降级 10,000 个点，尺寸等级改为 88.5% 微尘、10% 中亮点、1.5% 焦点星芒。默认焦点上限为 16 栅格像素并保留旋转四向星芒；降级上限 10，关闭星芒射线。中亮点/焦点采用预亮—短峰—快熄生命周期，只有焦点核心在选择性 pass 输出 HDR。

### 调校失败与最终参数

- 首轮把选择性 pass 的 alpha 直接放大后，河口汇流线在左右远海形成两条大面积白色雾带，重现上一轮的光污染。最终恢复汇流线受基础 `vAlpha` 约束，只让局部 glint 进入高能量区。
- 普通潮脊和星砂正常 pass 进一步限制颜色/alpha，避免重叠像素越过全局 Bloom 阈值；超级光刃的静态核心保持可读，但选择性辉光主要由 Tier 2 的局部彗星/镜面高光触发。
- 彗星选择性信号改为窄亮头：尾部只在正常 pass 可见，只有接近峰值的亮头以约 4 倍 HDR 颜色越过海洋 Bloom 阈值，避免整段主路径变成发光进度条。

### 验证

- 自动检查：`npm run lint`、`npm test`、`git diff --check` 通过；浏览器除既有缺失 `favicon.ico` 的 404 外，无 WebGL、shader 或页面运行时错误。
- 最终固定证据位于本地忽略目录 `outputs/ocean-core-convergence-2026-07-18/`：1920 × 1080 默认档三个时间点、1366 × 768 默认档三个时间点、1366 × 768 低动态两帧，以及 390 × 844 DPR 2 自动降级截图。
- 默认档黑色暗部（RGB 最大通道 < 26）占比：1366 × 768 为 86.67%，1920 × 1080 为 89.57%；高亮像素占比分别只有 0.320% 与 0.175%，未出现大面积白雾。
- 1920 × 1080 相邻时间点有 15.85% / 15.69% 像素产生大于 8 的通道变化；低动态在相机阻尼收敛后间隔 3 秒的两帧逐像素一致，证明波面、彗星和星芒均冻结。
- RTX 4070 Ti SUPER / ANGLE D3D11 最终代码 5 秒稳态复核：1366 × 768 与 1920 × 1080 均为中位 6.9 ms、P95 7.0 ms、最大 7.1 ms、绘制调用 92。最终 layer 注册修正前的同一候选版本曾完成两组连续 30 秒样本（P95 7.0 ms、绘制调用 92），但该样本不冒充最终代码正式证据；当前无头浏览器进程会在约 12—20 秒被测试宿主回收，因此最终代码的两组连续 30 秒记录仍需在稳定浏览器会话中补跑。

### 结论与未决项

- 本轮保留“暗底—细丝—潮脊—超级光刃—焦点星芒”的分级方向；汇流区继续是唯一最高亮度，暂停帧仍可读出河口扇出、横向汇流和向画外延展。
- T04/T06 不提前标为完成。集成显卡、120,000 粒子规模夹具、最终代码连续 30 秒正式采样以及 C-01 至 C-07 证据仍待补齐。
