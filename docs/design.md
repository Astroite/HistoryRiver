# 《落九川》产品与数据语义基线

> 状态：M2 基线 v1.1
> 更新日期：2026-07-20
> 技术合同：[tech.md](./tech.md)
> 视觉合同：[visual-design.md](./visual-design.md)

## 1. 当前定义

《落九川》是一件覆盖传说时代至 1949 年的纯视觉数据艺术作品。观看者站在人民光海一侧，仰望由历史人物逐年生命状态构成的天河。

当前作品没有产品 UI，也没有自动导览、悬停、选择或详情。观看者可以使用 UE5 编辑器式透视相机自由浏览三维场景；相机只响应用户输入，不推进年份，也不改变人物集合。环境流动是视觉材质的生命感，不是自动播放的产品流程。

## 2. 第一原则

### 2.1 人物是第一记录单元

一个人物拥有稳定 ID、规范名、异名、生卒或活动区间、所属时代、入选理由、来源和稀疏轨迹观察。事件、制度、作品与思想关系在当前版本都不是独立产品对象；若它们能支持某人的某年活动，只作为观察摘要或来源存在。

### 2.2 每个历史年是一个切片

内容边界为公元前 2700 年至 1949 年。历史纪年没有公元 0 年，因此共有 4,649 个有效年度切片。每个切片可以有已录入人物，也可以明确为空；空白不能用虚构人物填充。

### 2.3 事实、派生与视觉分层

1. 来源层保存文献、研究或机构资料；
2. 观察层保存来源支持的时间、地域与活动；
3. 年度派生层把人物活动范围物化为 `PersonYear`；
4. 视觉层把 `personId + yearIndex` 投影成线段、颜色与透明度。

视觉线宽、颜色、光晕和策展权重不是历史事实。算法生成的稳定河道偏移也不是人物位置。

### 2.4 未知优先于伪精确

没有位置证据的年份保持 `unknown`。两个地点之间不会自动生成精确路线；只有显式 `InterpolationRule` 才能插值，并且必须保存端点观察、方法和不确定度。当前核心数据没有启用正式插值。

## 3. 当前核心数据

M2 数据版本 `m2.1.0` 包含 11 个连续覆盖单元，每单元 4 位人物，共 44 人：

| 覆盖单元 | 当前人数 | 策展说明 |
| --- | ---: | --- |
| 传说与早期文明 | 4 | 传统纪年显式标记为 `traditional` |
| 商与西周 | 4 | 包含王室、制度与考古可见人物 |
| 春秋战国 | 4 | 思想、军事与统一进程的启动样本 |
| 秦汉 | 4 | 含一条跨 BCE/CE 人生轨迹 |
| 三国两晋南北朝 | 4 | 跨政治、军事与文化领域 |
| 隋唐五代 | 4 | 统一、女性统治者、文学与晚唐转折 |
| 宋辽夏金 | 4 | 当前均为宋人；辽夏金是明确缺口 |
| 元 | 4 | 统治、科学、书画与戏曲 |
| 明 | 4 | 建国、航海、思想与医药 |
| 清 | 4 | 帝王、文学与近代转折 |
| 晚清民国至 1949 | 4 | 生命可以越过 1949，视觉物化止于内容边界 |

这不是完整全史人物表。策展人数不表示人口、社会活跃度或客观重要度；时代之间的疏密也不能被解释为繁荣与衰落。

## 4. 视觉语义

- 一条可识别数据线对应一个人物；
- 相邻年度状态形成线段，顶点保留人物索引和 `yearIndex`；
- 有位置观察的年度可轻微影响水平投影；
- 未知位置使用稳定的视觉河道，不冒充地理事实，并以更低透明度显示；
- 逐年地理轮廓是独立艺术背景，不能当作人物数据库或精确疆域；
- 星空、装饰瀑流粒子、海浪与雾没有人物 ID，必须始终被理解为环境层。

## 5. 正式运行时边界

正式页面只保留 Canvas 容器和纯视觉暗角。相机导航属于视口基础设施，不是人物或时间产品交互。以下内容不属于当前产品：

- UI、按钮、导航、浮层、人物标签和详情；
- 自动导览、自动镜头切换、播放/暂停；
- 悬停、点击拾取、人物选择与键盘产品命令；
- URL 视图状态、五状态流程和通用 OrbitControls；
- 模拟事件点云、思想关系线和影响力维度切换。

M2-02 唯一放开的交互是 UE5 式相机导航：RMB 环视与飞行、鼠标平移/推拉、Alt 枢轴导航和 `F` 聚焦作品整体。它不得演化为人物选择或时间控制。若未来需要对象交互或事件数据库，必须以新的迭代合同重新定义，不能从 M1 代码恢复为默认方案。

## 6. 视觉与数据验收

- 初始第一眼仍是“九天、天河、入海、人民光海”，不是数据看板；
- 页面没有可见产品 UI，镜头不会随时间自动切换；
- 没有用户输入时镜头保持初始构图；视口输入只改变相机；
- 任一数据顶点能回到人物和年度；
- 任一年度切片成员与数据库查询一致；
- 传说、估计、争议、未知和插值不会被压成同一种确定状态；
- 44 人被明确描述为启动核心，不暗示完整全史；
- 环境粒子与人物数据线在代码和语义上分离。

## 7. 扩展原则

扩充数据时先新增来源和人物，再新增稀疏观察，最后重建年度状态与 Web 产物。新增人物不应要求修改渲染业务结构。新增事件、关系、人口层或交互产品必须另立合同。
